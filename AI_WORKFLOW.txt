# CleanShare AI Workflow

## Central Source Order

When sources differ, use this precedence:

1. The latest `CleanShare_Blueprint_v*.docx`.
2. `PROJECT_CONTEXT.txt`.
3. `DESIGN_RULES.txt`.
4. The `valuation_matrix` and files in `supabase/migrations/`.

Use `reference/mockup.png` as the visual authority, not as the authority for catalog scope.

## Implementation Workflow

1. Read `AI_WORKFLOW.txt`.
2. Read the latest CleanShare Blueprint.
3. Read `PROJECT_CONTEXT.txt`.
4. Read `DESIGN_RULES.txt`.
5. Review the relevant valuation matrix and migrations when catalog, eligibility or product positioning is involved.
6. Compare the requested visual scope with `reference/mockup.png` and the current implementation.
7. Analyse the request and identify affected files, content and dependencies.
8. Produce an implementation plan.
9. Wait for explicit user approval before implementation.
10. Implement only the approved scope.
11. Review responsive behaviour, accessibility and existing functionality.
12. Report modified files, relevant selectors and validation results.

## Positioning Consistency Check

Whenever marketplace positioning, categories, eligibility or product scope changes, verify consistency between:

- The latest Blueprint.
- `PROJECT_CONTEXT.txt`.
- `DESIGN_RULES.txt`.
- The `valuation_matrix` and current migrations.
- Public landing-page content.

Do not implement a positioning change while these sources contradict one another. Resolve or explicitly document the discrepancy first.

## Approval Rule

Never begin implementation before explicit approval.

Preserve visual fidelity and unrelated functionality. Creating, removing or materially restructuring sections requires an explicit approved request.
